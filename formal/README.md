# 独立形式检查与后端接入契约

当前 `protocol_lab.explore` 是共享参考语义的有界显式探索器。它只检查 `model/exploration.json` 给出的初值、事件域、深度以及 IR 中列出的状态不变量，输出可重放路径。不检查一般时序逻辑、进展性、公平性或无限重传。它没有独立实现一套形式语义，不能作为参考执行器本身正确性的证明。

v0.2 增加独立的 `protocol_lab.symbolic` Z3 后端。它不调用参考执行器的表达式求值或状态转移来构造约束；求解完成后才调用参考执行器重放见证。静态类型校验仍共享，翻译器本身尚未得到形式证明。

运行：

```bash
.venv/bin/python -m protocol_lab build
.venv/bin/python -m protocol_lab formal --depth 6
```

输出在 `artifacts/formal/`：

- `model.smt2`：可由新 Z3 进程直接载入的状态安全查询。
- `overlap.smt2`：相同事件下 guard 重叠的可达性查询。
- `result.json`：版本、边界、模型语义哈希、构建哈希、查询哈希、求解结果、见证或反例，以及参考重放结果。

语义与验证范围：

1. `seq32` 为真实 32 位 bit-vector；`int`/虚拟时间为数学整数；初始 ISS 与各事件字段符号化。其他初值来自 IR。
2. 动作按序编码，emit 在当前位置固定输出字段；定时器有 active 和 due，保留取消、重启、到期优先及同一截止时间按名称排序的语义。
3. 外部事件只能出现在所有有效截止时间之前；定时器事件必须在最早截止时间发生。多次定时器触发由多个符号步骤表示。
4. 检查 0 到 depth 个事件的所有已定义路径；终点后的空步仅用于补齐查询长度。非终点的死路前缀也会检查。
5. 查询未假设不变量成立；检查初值与每个后状态。另检查 arm 延迟必须为正；非法延迟产生反例，不通过剪枝隐藏。
6. 只建模已定义的 guard/transition，不覆盖未建模事件处理或证明模型完整性。ESTABLISHED 是此切片终点。未检查公平性、进展性、所有包字段的协议正确性或无界执行。

`bounded_pass` 表示 safety 与 overlap 查询均为 unsat，且一个非空求解见证通过参考重放。测试还固定四个参考场景，比较符号后状态、定时器和所有 emit 字段；删除取消动作、非法定时器、死路前缀和规则重叠均有独立回归测试。测试通过不等于证明两个执行器对所有输入都等价。

Ivy 生成器仍未实现。当前 PyPI `ms-ivy==1.8.26` 仅提供 CPython 3.10 的 wheel，无法直接安装到本环境的 Python 3.12；本轮采用 Z3 后端，未放置伪装为证明的 Ivy 文件。

Ivy 接入的验收条件：

1. 明确定义此 IR 子集的状态向量、原子 action、事件/定时器交错与 seq32 语义。
2. 对每个 AST 操作提供翻译；拒绝所有不支持的构造。不得静默忽略定时器或把 seq32 当作无界整数。
3. 区分环境假设、状态不变量与实现义务。记录使用的 Ivy 版本、完整命令、stdout/stderr 和退出码。
4. 对本例五个不变量完成可运行检查，并在故障变体中产生反例。
5. 将 Ivy 的反例转换为运行时事件序列，复现同一错误。
6. 比较同一初值/输入在 Ivy 与 Python 中的可观测行为，记录翻译语义保留的验证范围；交叉测试本身不等于已证明生成器正确。

首次可用实现可以采用有界 bit-vector 后端，但必须标明范围。若使用序列号抽象，应给出抽象对应关系及保留性质，不能从小整数模型自动推广到真实 32 位 TCP。

## IR 0.2 数据扩展

`bytes` 使用 Z3 `Seq(BitVec(8))`，没有隐式截断字节值或固定容量。新增长度、拼接、截断切片、整数减法/最小值，以及前向序列距离和半空间比较，精确定义见 `docs/semantics.md`。旧模型维持 IR 0.1。比较在相距 `2^31` 时不可比，模型不能把 le 的否定直接当作反方向 lt。

新增测试分别覆盖字节容量的深度 3 检查、全部 BV32 序列对的半空间谓词约束、非空字节串与回绕执行见证、两端切片边界、值语义回滚，以及错误序列推进的反例重放。这些是有限的后端验证范围，不是所有 AST 组合的等价证明。

已观察到同时包含序列距离/缓冲长度关系的混合查询在 10 秒时返回 unknown，某些 Z3 序列查询还会抛出 max unfolding 资源异常。检查器将后者记录为 unknown 并保存原因和查询，绝不输出 bounded_pass。字节容量性质和具体输入重放不能代替该混合性质的有界证明。

数据 profile 可额外启用 `symbolic_replay`。每个场景固定初值、事件字段、规则选择和时间，保存独立约束查询与见证，然后比较所有前后状态、定时器及 emit 字段。约束不假定后状态或不变量成立；三个故障测试在相同输入上查询不变量的否定。此路径只验证指定输入和规则，不能证明 guard 唯一性、覆盖完备或全输入安全。完整数据模型的 depth=6 safety/overlap 当前为 unknown，必须保留这一缺口。

新增的独立 `inductive` 路径对当前不观察字节内容的状态性质建立初值/逐规则保持/guard 组不重叠义务，采用经全 Seq 查询核对的长度公式和完整 32 位模整数。当前数据模型通过 117 条规则、14 个 guard 组的义务；原 BMC 状态不被替换。该证书不检查 payload 内容、liveness 或实机合规性。内容 eq/ne 在该投影中明确拒绝，未来新增内容性质仍需适当后端。准确的假设、查询结构、反例分类及验收见 [归纳义务说明](../docs/inductive.md)。

## 动作后目标与输出契约

新 post-target-v2 模型的条件输出和优先目标表由独立 Z3 后端显式编码；不认识 semantics 版本必须拒绝。固定输入查询只对已固定输入/choice 做等价常量化。状态归纳逐规则穷尽默认及所有声明目标，结果与输出/时序契约分开记录。新场景 0.2 的 expect_trace 是独立固定输入 oracle，涵盖该 step 自动触发的定时器和全部消息，不作为求解后态假设。协议或实现完整性仍未证明。
