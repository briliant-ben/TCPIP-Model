# TCP 精确 RTT/RTO 与 Karn 组合范围

模型 `model/tcp-rto.json` 通过 IR 0.3 overlay 组合 tcp-fin，沿用同一 UNA/NXT、发送／接收缓冲、FIN 序号及 rtx 定时器。176 条展开规则、121 个状态不变量；仍是单连接、16 字节容量、MSS=4 的有限 profile，不代表完整 TCP 或完整恢复算法。

## 规范及数值选择

规范基线为仓库固定原文 RFC 6298（June 2011）§2.1–2.5、§3、§4、§5.1–5.7，及继承的 RFC 9293 连接／数据语义。初始 RTO=1000ms，时钟粒度 G=1ms，alpha=1/8、beta=1/4、K=4；可选上限取 60000ms。首次样本 R 初始化 SRTT=R、RTTVAR=R/2；后续先用旧 SRTT 计算误差及 RTTVAR，再更新 SRTT。中间结果保持精确有理数，最终 `ceil(SRTT+max(G,4*RTTVAR))` 后施加 1s 下限和 60s 上限。统计不跨连接缓存；主动打开和被动接收首个 SYN 显式初始化。关闭清理新增采样统计，原 rto_ms 保留最后诊断值，下一次打开按原规则初始化。

每次至多一个样本，锚定原始 SYN、数据分段或 FIN 的序列区间及发送时刻。部分 ACK 保留原起点，直到累计 ACK 覆盖锚点末端才测量。序列距离使用完整 32 位模运算。重传覆盖样本尚未确认的区间时标记歧义，ACK 不产生 RTT 样本；没有覆盖该区间的旧前缀重传不污染样本。新发送可替换歧义锚点。没有 timestamp 扩展，也不从重传样本估计 RTT。

新 ACK 在重启计时器前更新 RTO；全确认关闭计时器，追加在途数据保留原截止点，超时退避翻倍并受 60s 上限约束。SYN 超时后的握手保持原 3s 初始化，直到取得新的无歧义样本才允许收缩。零窗口有在途探测继承有限前缀策略，完整 persist、delayed ACK、拥塞窗口、fast retransmit/recovery、SACK 及 timestamps 均尚未实现。

## 验收及剩余证明缺口

手算场景覆盖 SYN 首样本、精确 EWMA、部分 ACK、Karn、退避后新样本、SYN 丢失、FIN 和未来／重复 ACK。例：SYN RTT=333ms，后续样本=999ms 时 SRTT=1665/4ms，RTTVAR=2331/8ms，RTO 从 1581.75ms 向上取到 1582ms；1399ms 的 ACK 重启至 2981ms。固定轨迹明确检查 2980ms 不输出、2981ms 重传；这些是场景级时序契约。

独立完整字节重放、原 Seq/BV32 BMC、长度／模整数状态归纳分别报告。RTO 取值、样本区间、Karn 和更新顺序不变量不等于一般输出／时间正确性。继承的队列保存字节而不保存每个原始分段的全部发送时间：窗口变化导致的重新分段是否满足 RFC 6298 §5 的所有“不得过早重传”要求，仍需发送历史和通用时序契约验证；不能用当前手算截止点场景宣称该要求已完整证明。字节内容／输出对应、解释器与 SMT 翻译精化、独立实现数据证据也尚未完成。

归纳首次暴露新连接未清理估计器的任意合法前状态反例，保存在 artifacts/diagnostics/tcp-rto-initial；修复是显式初始化，不是限制前状态或删除不变量。Rocq 旧源绑定随 IR/后端变化失效，必须实际重跑检查；六个已有原语即使通过，也不证明本估计器或 EFSM 翻译。
