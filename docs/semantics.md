# IR v0.1：执行语义与 TCP 切片

## 通用核心

存储格式采用 JSON，使用 Python 标准库即可读取。可读格式和编辑器可以后续增加；版本与执行语义才是后端之间的契约。

`ir_version=0.1`；`semantics=flat-efsm-atomic-ordered-v1`。这是平面 EFSM 子集。当前不支持 HSM、并发区域、历史状态或任意非确定性选择，不能把这些构造静默降级为普通 FSM。

类型为 `bool`、`int`、`seq32`、`string`。`seq32` 只能使用相等/不等和 `seq_add(seq32,int)`；加法模 `2^32`。整数 `le/ge` 不接受 `seq32`。当前无通用串行数排序算子；扩展数据传输时必须明确定义半空间约束及相差 `2^31` 的处理。

表达式 AST 支持字面值、`seq`、`var`、`event`、`state`、`timer_active` 和显式 `op/args`。guard 返回 bool。禁止 Python 代码、动态导入、文件访问或 eval。

## 一步执行

1. 外部事件的时间必须是单调的整数毫秒。
2. 注入外部事件前，先按截止时间执行到期定时器；相同截止时间按定时器名称排序。
3. 定时器与网络事件恰好同一时刻时，定时器先执行。这是确定性环境选择，不是 TCP 的唯一合法调度。
4. guard 使用当前状态、变量、事件参数和定时器集合求值。零条规则可用为 `Uncovered`；超过一条为 `Conflict`。
5. 定时器到期动作执行前移除该定时器；普通事件没有隐式取消行为。
6. action 按列表顺序执行，后续表达式看到之前的赋值。输出字段在 emit 时求值并固定。状态在 action 列表执行完成后切换到目标状态。
7. 检查变量类型和全部状态不变量，写出事件记录。`dispatch` / `tick` 操作全部成功后才提交；失败会回滚整个调用，调用者应终止该失败分支。

`arm` 启动或替换定时器，延迟必须为正整数；`cancel` 取消不存在的定时器无副作用。定时器事件由运行时生成，禁止外部伪造。

不变量在初始状态和每个已完成的事件后检查，当前没有中间 action 不变量或时序逻辑。输出包正确性另由独立手写预期值、编码校验测试覆盖；状态不变量并未证明所有输出字段正确。

## TCP 配置

建模一个端点的主动打开，连接四元组、权限、路由与资源分配均假定有效。`net.synack` 是**抽象事件**：适配层应保证匹配连接，SYN/ACK 置位，RST/FIN 未置位，无 payload，报文格式与校验和有效。该事件的 `seq` 和 `ack` 字段仍由 IR 处理。

不发送 SYN data，所以可接受的 SYN+ACK 在此范围内需精确确认 ISS+1。这个 guard 不能直接推广到支持 SYN data 的完整 TCP。非法 ACK 当前会产生模型覆盖缺口，尚未实现其 RST/丢弃等处理。

选择初始 RTO=1000 ms 和指数退避，代表 RFC 6298 的一个算法配置；不是所有实现都必须采用相同初值。重传不推进 SND.NXT；握手完成后取消 SYN 重传定时器。`retries` 是已发生重传次数，未实现最大重试次数、用户超时或重试耗尽的 CLOSED 路径。

ESTABLISHED 是本切片终点。`rto_ms` 是 SYN 阶段的退避值，终点之后不驱动数据传输。RFC 6298 §5.7 的握手后数据 RTO 处理、RTT 采样及 Karn 算法均未实现；因此本模型不能作为完整 RTO 实现使用。

固定初始 ISS 仅为可复现实验，并未建模实际 ISS 选择算法。JSON 里的普通整数值依照字段类型解释；表达式里的序列常量用 `{"seq": number}` 区分普通整数。

## 网络、丢包与观测

环境在场景中显式列出何时投递 SYN+ACK。丢包通过“不提供该次 SYN 对应的响应”体现；`drop_outgoing` 是环境注释，并会校验指向的输出包确实存在、为 SYN。当前没有独立运行的对端或网络队列，注释不是通用网络仿真器。

合成 PCAP 的观测点是本地端点的出口和入口，因此丢失的初始 SYN 仍在 PCAP 中可见。PCAP 不编码 drop 元数据，drop 标注保存在 `packet-map.json` 中。地址为文档地址 192.0.2.1/192.0.2.2，端口为 40000/8080，均为编码配置，不是 IR 状态。

比较器采用本切片的有序投影：direction、flags、seq、ack、time_ms。忽略窗口、选项及 IP 字段；时间默认容差 50 ms。必须先对真实序列号、时间原点和观测点做归一化。它不判断完整 TCP 行为，不支持一般非确定轨迹接受关系。

## 来源与义务

每个 transition 和 invariant 指向 requirement ID，requirement 记录官方条款链接、人工解释、义务强度和类别。`PROFILE-SCOPE` 是环境假设，不是 RFC 要求；不变量是工程推导，关联的条款不是对该公式的逐字规范表述。

RFC 原文与 manifest 中 SHA-256 一起固定。下载日期表示取回基线的日期；尚未进行独立 errata 清单审查或标准更新监控。保存的 RFC 保留其原始版权及法律声明。需求解释不修改原文。

当前没有自动 RFC 提取、规范覆盖率百分比、guard 全局完备性证明或 SHOULD 例外推理。JSON 静态校验与有界探索只是其中两道检查。

## v0.2 独立检查与观测

Z3 后端另行编码此 IR 子集，覆盖符号化 32 位 ISS、带类型的事件字段和整数时间。它检查已定义路径的有界状态安全与 guard 重叠，不通过假定不变量成立来筛掉失败路径；正定时器延迟是额外的运行时安全条件。详见 `formal/README.md`。

PCAP 归一化器不调用合成编码器。它按显式四元组过滤连接，保留包顺序，将真实双端 ISS 映射到模型序列空间，以第一个选中 SYN 为时间原点。它支持经典 PCAP 的 IPv4/TCP active-open 切片，拒绝选中连接的分片、payload、额外控制 flags 和无效格式；不做去重、TCP 重组或通用抓包语义推断。

`assess` 对构建快照和外部证据分别校验。语义文档、RFC manifest、IR、运行时代码或场景改变会使旧构建失效。观测还绑定一次成功的 packetdrill 运行，不能把旧抓包和新运行记录直接组合成通过。哈希用于检测过期或内容变化，不为操作者声明的来源提供真实性证明。
