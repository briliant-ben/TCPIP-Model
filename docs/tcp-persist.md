# 有限无在途起始的零窗口 persist 开发模型

`model/tcp-persist.json` 继承 tcp-delayed-ack，共用 UNA/NXT、snd_buf／rtx_buf、FIN、ACK/window、delack 和逐字节发送历史。所有探测、队列移动、资格、截止点、退避、清理与定时器归属均为显式 IR AST；未注册为当前 11 profile，须单独验收。

规范基线：固定 RFC 9293（August 2022）§3.8.6.1，MUST-36/37 支持有字节的零窗口探测并允许响应探测的连接保持，SHLD-29/30 建议 RTO 后首探测及指数增加间隔。选择：首次出现“窗口为零、无在途、存在排队数据”的发送需求时，以当前 RTO 启动 persist；后续间隔独立倍增至 60s。这个上限是模型配置，不是 RFC 固定值。探测期间不改变正常 RTO 估计器或其重试计数，不设置探测次数上限；资源管理／用户超时策略未增加。

首探测发送排队首字节，移动到同一 rtx_buf、推进一次 SND.NXT；后续未确认时重发同一字节，不重复消耗序列空间。累计 ACK 确认该字节后，若仍有排队数据且窗口为零，保持原间隔与截止点，下次发送下一个新字节。重复零窗口 ACK、追加数据和 blocked transmit 均不延长既定期限。普通在途数据随后缩成零窗口仍走父模型已有 RTO 子集，不被新模式夺取。

原 CL-INV-TIMER 假设所有数据／FIN 在途均由 rtx 定时器负责，在引入 persist 后需要替换为显式所有权关系：普通在途仍必须有 rtx；persist 从无在途起始，只允许最多一个探测字节并独占 persist 定时器，此时禁止 rtx。保留共享队列／序列号不变量，并新增域、双定时器互斥、probe 历史、截止点构造及不得过早探测不变量；不是删掉定时器安全义务。窗口恢复后将尚未确认的探测字节交回正常 RTO，起算当前 RTO；ACK 已清空时取消 persist。关闭／重置清理归属与计时。

persist 不从探测取得 RTT 样本；正常数据的估计和 Karn 原规则仍保留。探测携带当前累计确认／本地接收窗口，故实际探测输出可取消待发 delayed ACK；提前定时器故障只等到声明截止点，不发包、不退避、不加计数。同刻定时器沿名称排序，已到期探测先于同刻外部窗口更新。

范围：单连接、16 字节、MSS/RMSS=4，ESTABLISHED／CLOSE-WAIT／发送侧 FIN-WAIT-1，以及 FIN 尚未发出的 CLOSING／LAST-ACK 可进入。FIN-only 零窗口探测、完整 sender SWS、资源／用户超时策略、拥塞与快速恢复、通用输出／翻译／实现精化及独立实现数据证据未完成。不得以无界次数整数或长期固定场景宣称活性／公平性证明；状态不变量也不自动证明 timer 实际截止点与所存 deadline 的语义对应。后端、固定字节／输出场景与实际实现验证分别报告。
