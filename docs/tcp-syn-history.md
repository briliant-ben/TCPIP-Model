# SYN 超时发送历史开发切片

开发 overlay `model/tcp-syn-history.json` 继承 tcp-tx-history，保持原有数据／FIN 历史、一个 rtx 定时器、RTT/Karn、序列空间及用户超时。增加 SYN 控制位置的最近实际发送时刻、在途标记及显式超时资格判断。已列入 suite 注册表，使用显式单项分组配置；本轮重建验收完成前不沿用旧开发结果，也不代表完整 TCP 打开或恢复模型。

规范基线：RFC 6298 §5 的超时不得早于上次发送后的一个 RTO，与 RFC 9293 §3.10.7.3 同时打开的即时 SYN,ACK 回复、§3.10.8 重传队列超时处理组合。即时回复不能按“超时重传”延迟；但它刷新实际 SYN 序列空间发送历史，并把替换后的 SYN,ACK 的 rtx 截止点设为当前时刻加当前 RTO，用户超时不延长。之后若旧定时器先到而该控制尚未等待当前 RTO，则只重设剩余等待时间，不输出、不退避、不增加重试次数，不把未发生的超时发送记入 Karn。真正超时发送沿用原退避，并更新最近发送时刻。

固定对照：原模型在 0ms 发 SYN、900ms 发同时打开的 SYN,ACK，1000ms 按旧截止点再次发 SYN,ACK，间隔仅 100ms。该控制历史在原 profile 明确排除；对照是模型未覆盖，不是 Linux/lwIP 或 RFC 实现缺陷证据。新 overlay 在 900ms 将截止点设到 1900ms，1000ms 无事件／输出，1900ms 才发送并退避。额外的资格等待分支覆盖提前定时器故障或归纳任意前状态，不把这种故障注入当作正常可达轨迹。保留原模型和轨迹，不通过放宽比较器修正差异。

范围仅覆盖原抽象事件已声明的普通主动／被动及同时打开、超时、ACK/reset/abort 清理；没有增加 SYN payload/TFO、timestamp 或一般 options/reset/重复 SYN 处理。SYN-SENT / SYN-RECEIVED 另显式约束输出控制 flags，非 SYN 状态清理发送时间／在途标记。接收 ACK 的同刻定时器先执行规则保持。

状态不变量和从实际输出重建的独立年龄断言分别检查；后者不使用模型自报时间槽，能够发现丢失登记的故障。形式检查、固定完整字节重放及未来统一验收分别记录。原九模型的 IR 不依赖本 overlay；注册表及检查器变化后仍须全部实际重建，不将开发测试当作新增实机或完整正确性证据。

重设即时回复的截止点还避免在一个未达到实际发送 RTO 的旧截止点触发 RFC 6298 §5.7 的 SYN 超时解释歧义：普通响应后未发生真正超时的 ACK 不应被旧计时器制造为 SYN 丢失；若真正超时已先发生，再同刻处理外部 SYN/ACK，则保留原重试计数和 3s 数据初始化。早定时器故障分支是防御性模型域，不等价于正常协议超时；完整故障／环境精化仍待验证。

统一 SYN profile 复用原 97 个数据／恢复场景并加入 3 个 SYN 时序契约，共 100 个固定输入；主 BMC、主归纳和补充分组分别记录，单项分组不替换原 unknown。

三种打开场景使用显式 tcp-connection-v1 捕获投影：分别从每个方向实际 SYN 建立原点，单向 SYN 超时不虚构对端 ISS；旧 active-open 投影不放宽。见 connection-capture.md。
