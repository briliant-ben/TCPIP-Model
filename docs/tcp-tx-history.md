# 有限数据／FIN 发送历史与超时重传

开发模型 `model/tcp-tx-history.json` 声明式继承 tcp-rto。它保持同一连接状态、序列号、缓冲、RTT 估计器和 rtx 定时器，增加 16 个整数毫秒的在途字节时间槽及独立 FIN 时间。容量仍为 16 字节、MSS=4；不代表完整 TCP、SYN 超时历史、fast retransmit 或拥塞恢复完成。现已注册为第九个 suite profile；初次统一重建验收的实际结果见实施日志。

规范依据 RFC 6298 §5：超时重传不得过早。该切片针对数据／FIN 的 timer.rtx 路径，用本次退避前的当前 RTO 判断每个待重传字节是否自上次发送起已等待至少一个 RTO。不是以整段队列的最早时间替代每个字节的发送时间，也不假定历史时间按序单调。

新数据发送时，给新增在途字节登记当前时刻；累计／部分 ACK 按其真实移除的字节数移动时间槽，清理已离开队列的位置。FIN 占独立控制序号，登记独立时刻。超时仅选择满足时龄条件的最旧连续前缀，再受原窗口／MSS 限制；只更新真正重传的字节时间。Karn 的覆盖区间使用实际输出长度。若最旧字节／FIN 尚未到期，明确等待其截止时刻，不输出空重传、不增加重试次数、不退避 RTO。该等待分支也覆盖归纳检查中的任意合法定时器前状态，不声称提前截止的定时器在正常轨迹中一定可达。

保留原 RTO 模型的历史反例：21ms 发出两字节，1000ms 追加四字节，旧前缀策略在 1021ms 重传四字节。新模型应仅重传前两字节。旧模型和原证据保持，以独立测试和明确的新场景验收行为修正，不修改上游实现或放宽比较器。

状态不变量分别约束时间槽、空位置清理、选择长度，以及本次重传的最小字节时龄。它们只证明已声明的状态／快照义务，不能单独证明快照与所有真实输出、历史轨迹之间的精化。另用从实际发包重建序号／时间的独立测试断言检查提前发送、错槽／错裁剪故障。固定完整字节符号重放及一般状态归纳分别记录；unknown 保留，SYN 和更完整输出时序证明仍需继续。

统一流程同时保留原归纳结果和独立补充精化命题。补充层逐一绑定所有 unknown 目标的原 SMT、完整断言／分组覆盖及实际重查，并要求非空完整字节样本。不会把原 unknown 或 BMC 结果直接改为通过。该 profile 仍有 180 条声明规则、144 个不变量和 217 个声明目标检查；具体资源结果可能为 unknown，必须以当前报告为准。历史开发证据 artifacts/tcp-tx-history 对应 1cd5a3b，当前工具变化后不能只重绑旧哈希；新的统一证据位于 artifacts/suite/tcp-tx-history。
