# 显式有限分段选择

此开发overlay在共享tcp-limited-transmit继承链上添加choice.segment(count)，原app.transmit的确定分段选择保持。count是显式模型调度选择，不是新socket参数、真实网络输入或自动PCAP许可。正数count不得超过现有MSS／待发字节／rwnd／cwnd预算；父FIN、RTT、Karn、逐字节发送时间、idle缩窗和队列动作完整保留，只将take换成已验证count。无待发／信用耗尽／FIN-only／非法count机会未定义，拒绝为Uncovered，而不是静默发送或认定实现错误。

RFC9293 August2022 §3.7将MSS作为最大segment text限制，并不要求每段填满。仅此有限正长度前缀策略纳入本模型；不据此涵盖Nagle、所有分段算法或任意输出时机。生成器将父动作前缀的赋值精确替入take表达式，形成guard可用的原始前态上界；不能直接使用动作执行前尚未更新的cwnd来跳过idle预算。遇到前缀非赋值效果或父规则结构改变显式拒绝。生成器仅输出JSON，参考执行和独立形式后端只读取IR。

此阶段增加8个已声明选择规则及可检查的标量预算／序列关系，尚未注册suite。字节内容和顺序需独立完整字节重放，不由长度归纳替代。沿用SMSS4／队列16及32位序列号，有限范围明确；原主unknown不因选择引入而回填。

两个2字节段可作为既有lwIP四字节窗口实验初始数据前缀的候选见证。候选的严格逐包比较只支持明确截止时刻的前缀；完整旧Difference、raw PCAP和后续未匹配事件保持。没有因此证明完整应用调用对应、无限调度、一般允许输出、RTO／窗口策略或实现精化，更不代表完整TCP或Linux证据。
