# Independent lwIP Limited Transmit observations

Uses the unmodified stream C driver, pinned upstream lwIP2.2.1 and a private evidence-module instance bound to tcp-limited-transmit IR. No host TCP, internal PCB congestion-state reads, upstream changes or oracle normalization changes. Same <=16 written bytes/64 peer bytes/64 events/200ms bounds. Each experiment initially writes only four bytes, outputs at21ms, then optionally queues additional data before first/second scripted duplicates at30/31ms. A no-flight pure ACK at11ms establishes the existing upstream window metadata before data; this is explicit input, not capture filtering.

The model's IW4 and upstream's initial window policy remain distinct; initially only four bytes exist on either side, avoiding an initial burst-choice divergence. No third duplicate, RTO, real peer loss or complete acknowledgment claim. Unacknowledged bytes deliberately remain at the capture endpoint. Independent receiver callbacks, raw PCAP, strict ordered 0ms Difference, reference/full-byte query reconstruction and input/build/artifact hashes use the unchanged stream evidence machinery.

RFC3042 January2001 §2 and RFC5681 September2009 §3.2 specify first/second-duplicate new-data opportunities with unchanged cwnd. The pinned tcp_in.c duplicate branch has no new-data Limited Transmit operation for dupacks<3; source interpretation is an inference, not a measured internal variable or a demonstrated RFC bug. RFC3042 uses SHOULD; a strict model/implementation difference does not by itself prove a normative violation. Lack of a packet by31ms does not claim never-transmission.

Actual initial captures: no queued new data produces no additional packet; one queued segment is sent at30ms and matches the model; with twelve queued bytes lwIP sends all three four-byte segments at30ms, while the model sends one at30ms and one at31ms. Source explanation: tcp_input's normal tcp_output can flush pending bytes within the upstream initial congestion window, irrespective of a dedicated Limited Transmit operation. The one-segment match does not establish internal LT support or equal cwnd. The original test assumed queued data would remain entirely unsent; its failures and original captures are archived in diagnostics/limited-transmit-induction-epoch-v1. Corrected tests assert the actual burst without changing the strict comparator.

Run `.venv/bin/python ports/lwip-limited-transmit/run.py`, repeat with `--verify`, or select another bound scenario and a distinct `--out`. Standalone tests: `.venv/bin/python ports/lwip-limited-transmit/tests.py`. Exit1 from execution means a captured difference; successful evidence verification may accept that difference. Binaries are rebuilt locally and not committed. Existing recovery/window/FIN and 2750ms SYN-loss evidence is separate; none is Linux evidence.
